## Design

### One registry for public pages

`src/seo/pages.ts` lists every indexable static route with its title and
description. `pageMetadata(path)` turns an entry into `Metadata` with the
canonical URL, `og:url`, title, description and social card; entity pages
build the same shape from `src/seo/entities.ts` through `seoMetadata`. Private and utility routes use
`privateMetadata(title)` (`noindex`). A test walks `src/app/**/page.tsx` and
requires every route to be either in the registry, an entity route, or in the
private list, so a new page cannot silently miss metadata or the sitemap.

The root layout sets `metadataBase`, the `%s | Magick.ly` template, the site
description, Open Graph defaults without a title (so Next fills `og:title`
and `og:description` from each page) and `summary_large_image` cards. It never
sets a canonical, which would otherwise be inherited by every page.

Client pages are split: `page.tsx` becomes a server component that exports
metadata (and, for entity routes, `generateStaticParams`, `generateMetadata`
and `notFound()`), and the old component moves to a sibling client file.
The Sephirah and path pages become static like the planet and grade pages.

### Indexing policy

| Routes | Policy |
| --- | --- |
| Home, about and the sections: astrology, chat, Enochian, Golden Dawn, built-in rituals, geomancy, Kabbalah, study (and their static children) | index, sitemap |
| `/astrology/planet/*`, `/gd/grade/*`, `/kabbalah/sephirah/*`, `/kabbalah/path/*` | index, sitemap, unknown ids 404 |
| `/doc/<id>` public SQL rituals | index with the ritual title; not in the sitemap (needs the database) |
| `/doc/<id>` otherwise, `/doc/*/edit`, `/offline/ritual`, `/signin`, `/admin`, `/upload`, `/temples/**`, `/chat/train`, `/study/<set>`, `/study/info/<set>`, `/gd/components` | `noindex`, not in the sitemap |
| `/api/`, `/chat/api/` | disallowed in `robots.txt`, except the public renderers `/api/render/` and `/api/treeOfLife` that social cards and saved rituals reference |

Query variants keep their canonical page URL. Social cards never carry
shared state (plan 027).

### Sitemap and robots

`src/app/sitemap.ts` and `src/app/robots.ts` replace `next-sitemap`, its
postbuild step, config, generated-file ignores and the committed
`public/robots.txt`. The sitemap is the registry plus the four entity lists.
It omits `changefreq`, `priority` and `lastmod`: search engines ignore the
first two, and a build timestamp is not a real modification date.

### Empty shells

The Tree follows the recommended fix: a presentational `TreeOfLifeView`
renders both the linked state and, as the Suspense fallback, the default
settings, so the prerendered HTML carries the default tree, controls and
Sephirah links. Settings parsing moves to a tested pure module.
`DocRender` gets the same split (`DocView` takes the search params), and the
built-in ritual shell renders the default ritual as its fallback. Shared
links briefly show the defaults before hydration swaps in the linked state;
the service worker's public ritual shells carry the same default text.

### App bar, headings and snippets

Only the sign-in link needs the query (for its callback), so it moves into
its own Suspense with a pathname-only fallback, and the rest of the bar and
the spacer render on the server. The layout renders the bar without a
Suspense boundary of its own: React outlined a completed bar boundary on
large pages and revealed it by script. The bar title becomes the page `h1` when it
names the page; entity pages get their own `h1`. The recovery banner gets
`data-nosnippet`. The zodiac cells stop linking to missing pages.

### Structured data and social cards

The home page carries `WebSite` JSON-LD (Google's site-name markup). A
statically generated route, `/og/<page path>.png`, draws 1200×630 cards with
`next/og`: the page's name and section, and art from the section tile or the
closed component renderer (Tree, tablet, candlestick, shewbread, geomancy
chart, default rose sigil), all fixed at build time.

## Adversarial review

An independent review of `bb8a77e..b68cebd` (web-application profile) found
no blockers. Its three substantive findings were reproduced and fixed in the
last three commits:

- **Unstyled prerendered rituals.** Nothing registered styled-jsx for server
  rendering, so the prerendered rituals had their `jsx-*` class names but no
  CSS. The Neophyte painted 54,024 px tall before the client render took it
  to 40,288, and section links landed in the wrong place. The Sephirah, path
  and moon pages had the same problem before this work. With the registry, the
  Neophyte's script-free HTML lays out at 40,180 px against 40,191 hydrated,
  and `#Closing_of_the_0=0_Grade` lands on its heading.
- **Unknown ids cached.** Unknown entity ids rendered on demand and stored
  year-long 404 entries. They now 404 without rendering, and no cache files
  appear.
- **Hydration error on some 404s.** The static 404 page is prerendered at
  `/_not-found`, so 404s under titled sections (`/gd/nope`, `/chat/x`,
  `/temples/nope/x`) threw React error #418 once the app bar rendered on the
  server. In fresh tabs the error still appears on `b68cebd` and not after
  the fix. The browser's router reports the segment as `_not-found`, without
  the slash.

Accepted as they are:

- `%25` in an entity id gets a 500 from Next's own parameter decoding; planet
  and grade pages already behaved this way.
- Six planet pages are thin; see the follow-ups.
- `/chat/train` and `/admin` show two `h1`s: the app bar's and the page's.
  Both pages are `noindex`.

The review also confirmed:

- All 94 sitemap URLs return 200 with a matching canonical and `og:url`, one
  `h1`, one app bar, a unique title and a working card.
- Every private route has `noindex` and no canonical, and an unknown
  `/doc/<id>` leaks no ritual title.
- The og route rejects traversal and case variants.
- No hydration errors appear on the 94 pages, query variants or private pages.
- The new service worker installed, removed the old shell cache, and found
  every shell asset in its precache.
- All 59 internal links it sampled return 200.

Private pages (`/signin`, `/temples`, `/study/<set>`, stored rituals that are

entity ids answer 404, and `/gd/grade/0%3D0` serves the `0=0` page with the

no outlined streaming segment.

Ritual shells are larger now that they carry the text and its styles: 874,
528 and 485 KB for Neophyte, Zelator and Theoricus, or 63, 43 and 40 KB
gzipped. The service worker warmed all three in Chromium, and every `/_next/static`
asset they reference is in the build's precache, so its shell check still
passes. Offline reading of a warmed shell was not repeated after the change.

The 94 cards take 6.4 MB (median 38 KB); palette quantisation cut them from
25 MB.

Browser checks ran in Chromium 152 against `next start`. Safari was not
checked; nothing here depends on WebKit-specific behaviour. The Vercel
standalone build was not run locally, and the release workflow runs it. The
card route is fully prerendered and returns 404 for anything else, so its
function should never render at runtime; its trace therefore does not
include the renderer fonts.

## Archangel data

On 17 September, after this record, the data behind the Keter follow-up was
fixed in its own commit.

- **Keter:** its row spelled `archangelIdId`, so its archangel never resolved.
- **Missing rows:** `archangels.json5` also had no rows for Metatron, Ratziel
  or Sandalphon, so Keter, Chochmah and Malchut showed no archangel on their
  pages, in their descriptions or in the Tree's archangel fields.
- **Haniel:** his `sephirahId: "netzach"` sat at the top level of the file as a
  stray entry.

The Hebrew names used are מטטרון, רזיאל and סנדלפון.

The Theoricus ritual's Tree shows `archangel.name.he`, so its image changed.
The old image was 142,962 bytes, SHA-256 `00c82f49…`. The new one is 151,079
bytes, SHA-256 `b66fab61bf2f1c4015440bff9d6875a380b48cb1159d69f75c8b50459b6cfed5`,
and was reviewed side by side with the old one. The outline identity is
therefore now `magickli-tree-image-outlines-v2`, and the golden test pins the
new bytes. With the old data, the renderer still reproduces the v1 bytes
exactly.

Effects on published rituals:

- Offline bundles already published keep their stored bytes. Each ritual's
  next publication draws the new image and its own manifest.
- A publication that starts before the deploy and is retried after it would
  build a different manifest under the same operation, and so be refused as an
  operation conflict. Starting a new publication resolves that.

## Follow-ups

Recorded in [current status](000-current-status.md):

- After deploying, resubmit `/sitemap.xml` in Search Console and remove
  `/sitemap-0.xml` if it was submitted directly; that URL is now a 404.
- Done 17 September: Keter's `archangelIdId` key and the missing archangel
  rows; see [Archangel data](#archangel-data).
- `/astrology/moon` prerenders build-time dates and the server's time zone,
  then replaces them on hydration. It should compute its dates only in the
  browser.
- Planet and grade pages still show raw JSON rows, and several planets
  (Earth, Uranus, Neptune, the nodes) have almost no content. Readable
  correspondence tables would help readers and search alike.
- `/study` still prerenders nothing but the recovery banner. Its set list is
  static data and could prerender like the Tree.
- Public SQL rituals are indexable, but they are not in the sitemap, which
  would need the database at request time.
- App bar titles such as "Keys" and "Dictionary" are short for headings;
  fuller names in `pathnames.ts` would read better.
