# Local acceptance and shared test sign-in

The remaining multi-account acceptance journeys run against an isolated local
production build, real PostgreSQL and MinIO. Three synthetic Better Auth sessions
are generated by the external `local-acceptance:seed` task; the deployed app does
not enable password login. See [the fixture instructions](../scripts/local-acceptance/README.md).

Loom's new development-only test-login helper is separate from that fixture. It
owns bounded POST parsing, loopback/origin checks, safe redirects and forwarding
Better Auth cookies. Each application retains its test identities and permission
policy. Magickly requires exact preseeded users; Porty retains its separate admin
grant fixture; Shadowlang retains its existing test roles and credits. The actual
production server returns 404 for this route even with the opt-in variable set.

The operator approved publishing shared commits `b92fc5c` and `af9d485` on
14 September. The normal Loom release workflow succeeded for 1.27.0. After npm
made the artifact available, its integrity and a clean installation were verified.
Magickly adopted the exact published version through `loom dev published` in
`388123d`; its production Loom check, 59 auth tests and typecheck pass. Porty
adopted it in local commit `7a3eac1`; Shadowlang in `033b173`, with its full
pre-commit passing 926 tests, types and Biome. Neither reference app was pushed
or deployed. This is not a Magickly production promotion.

Shadowlang's production Loom check reports two confirmed static-analysis false
positives: it follows an erased `import type` into server modules, and it does
not recognize the workflow's parameterized `node --env-file` migration wrapper.
The actual import emits no runtime dependency, and the wrapper loads the pulled
target environment before spawning migrations. These shared checker limitations
remain follow-up work; no app runtime or release changes were made to satisfy
those patterns.

## Browser evidence

Temple creation, its atomic first-admin membership, join codes, grade/admin
changes, group membership and global-admin separation passed using three separate
local browser contexts. The initial temple journey ran against the frozen
`47d521d` runtime. The storage journey uses a production build from `d3567c4`
with reviewed local storage changes, build ID `UTMFqEOXxi83Ku0q0Y5vY`.

Private PNG upload, inserting the returned attachment into source, saving,
publication, reader access and offline discovery passed. An offline direct
ritual reload retained its image. Reader upload permission remained denied.
After a dirty editor draft was persisted, disconnecting and advancing the clock
beyond fourteen days hid the source, CodeMirror, script handle, Save and recovery
controls. That browser context was closed without rolling its clock backwards.

Online revocation testing found an initial-load race: a permission refresh could
be attempted while account activation was still checking, then never retried.
A standard reconnect event did enforce denial and purge. A bounded readiness
retry is implemented for both the reader and source editor. The first rebuilt test
also exposed cancellation of an already-started check by account activation;
the fix now queues a retry for that specific lifecycle reason, while avoiding
a loop from its own successful cache updates. The fix also preserves the awaited
post-save source refresh before publication.

Cached reload then exposed a second cancellation source: registering a downloaded
ritual starts an asynchronous inspection while the old coordinator snapshot still
reports ready. Discovering the cached capability cancels the permission token
before its first network call. A deterministic real-coordinator/IndexedDB test
now reproduces that sequence. The helpers report interruption only before a
permission response is accepted, allowing one queued retry without looping on
their own accepted cache changes. The UI also keeps pending checks while hidden.

The combined fix is committed in `803c234`. Production build
`-VN2VtQuqFqstawyEqjCg` passes ordinary online reload after the creator lowers the
reader's grade: the permission request returns a signed denial, the rendered
ritual disappears, and its cached bundle is removed. A later offline direct
reload remains unavailable and the offline catalog is empty. This receipt had
zero cached images before revocation, so it does not establish image removal;
an image-present rerun remains outstanding. Revision v4 subsequently published
with one verified image asset, but the operator paused work before the reader
download. All eight committed files match the runtime's frozen source manifest.

The creator editor exposed a separate initialization defect: source and draft
storage contained the saved source while CodeMirror appeared blank. The one-shot
source dispatch can precede view creation. Inserting the existing attachment
preserved and displayed the full source, so no data loss was observed. The fix
and delayed-view/lock regression tests have not been started.

Study reviews persisted under the reader account online and offline, including
after an offline restart of a fully cached document. Three reviews eventually
reconciled to exactly three SQL reviews. Reconnecting after the offline restart
left one event queued despite successful session checks; an ordinary online
reload drained it. The reviewed fix serializes fresh identity checks across the
bridge, reader and editor, and fences queued checks on explicit sign-out. Its
browser retest passes on production build `PWTfoiStrHRiqe9EEVTAH`: one answer
survived a cold offline reload, then drained on reconnect without navigation,
advancing SQL from version three to four exactly once. The fix is committed in
`3586b18`. A client-side-only visit did not warm the full study document, whereas
loading that document online did; this is a current offline-navigation limit.

MinIO protocol tests cover real presigned PUT/checksum headers, immutable writes,
duplicate reconciliation, finalized reads and bundle reads. A failed conditional
write closes a MinIO connection; the local adapter disables connection reuse so
the immediate reconciliation read opens a fresh socket. R2's transport retains
its existing behavior. Local storage requires explicit opt-in, numeric loopback
origins and database URLs, and no Vercel marker.

The integrated candidate with both reviewed fixes passes 4,335 tests with 16
opt-in tests skipped across 163 files. Full TypeScript and Biome pass, with 45
existing Biome warnings. The suite's socket and FIFO fixtures require host
permissions unavailable in the restricted sandbox. Local
browser evidence complements the earlier real Neon migration rehearsal and two
successful Google OAuth sign-ins. A small deployed private R2 journey remains
necessary; local PostgreSQL 15 and MinIO do not establish Neon 18 or R2 parity.

## Evidence locations and limits

Nonsecret browser results are under ignored
`output/playwright/local-acceptance/`. Runtime metadata and frozen-file hashes
are under `/tmp/magickli-local-runtime/`; integration logs are under
`/tmp/magickli-local-acceptance/`. Credentials and session state remain in private
files and must not be copied into reports.

The first upload browser crashed during temporary-filesystem inode exhaustion.
Before retrying, SQL and object inspection proved no upload had been persisted.
Removing regenerable dependencies from obsolete rehearsal copies freed inodes;
the single subsequent upload passed. This is not evidence of an application
upload failure or proof of the crash's exact cause.

Later `Session closed` failures had a different, proven cause: the test script's
response listener used `URL` in Playwright CLI's restricted evaluation context.
Daemon stderr showed an uncaught `ReferenceError`, terminating the driver before
it returned browser evidence. Available memory and inodes were sufficient. The
harness parser was corrected and the browser journey then completed; application
code and its build were unaffected.

The reusable modernization skill includes these lessons but remains an ignored
draft until the entire modernization and production cutover finish.
